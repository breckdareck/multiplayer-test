# Bot ambient texture: churn, replies, image emotes, reputation, banter

ADR 0011 built the skeleton of the Erenshor-style ambient population (speech
pipeline, personality archetypes + roster, seeding, companion commands, trade
consent). This layer adds the *texture* — the behaviors that make the
population read as people rather than scenery. Nine additions in three
slices; the architectural choices worth recording:

## Decisions

- **Login/logout churn.** The population is no longer static: `BotManager`
  periodically "logs off" an online bot (despawn — its save row persists) or
  "logs on" an offline identity, with `"<name> logged on"` feed lines sent to
  every real player. The churn pool is the union of authored config bots and
  the roster, so identities accumulated by `/bot spawn random` keep coming
  back. The **roster gains `class` and `last_seen`** per entry so an offline
  identity can be respawned faithfully — identity stays file-based (ADR 0011),
  it just grows fields. Bots partied with a real player, under a companion
  command, or in a stress test are never churned out.

- **Replies to name-mentions.** `ChatManager._broadcast_message` (already the
  single server-side chokepoint for player chat) scans each message for the
  names of bots on the sender's map and schedules a delayed
  `try_speak("reply", force)` per mention. The client knows nothing; a bot
  "hearing" you is entirely a server-side text scan.

- **Emotes are pixel-art icons, not text bubbles.** Generated by
  `tools/gen_emote_icons_px.py` on the same zero-dependency
  `tools/pixelart.py` canvas as the item/ability icons, into
  `assets/sprites/Emotes/generated_px/`. The chat-feed line stays text
  ("*waves*"); only the overhead bubble becomes an icon. `EMOTES` maps each
  command to `{text, icon}`, and the `_show_emote` RPC carries the command so
  clients resolve the icon locally. Bots emote through
  `ChatManager.bot_emote()` — a visual-only twin of `bot_say()` with its own
  (shorter) global gap, so sitting in town doesn't consume the speech budget.

- **Reputation lives in the roster.** Per-bot, per-player interaction scores
  (parties shared, trades, replies) accumulate under the bot's roster entry —
  NOT Postgres, same reasoning as ADR 0011. Greetings tier by score:
  `greet` → `greet_familiar` → `greet_friend`. The payoff is cross-session
  ("Bob remembers me"), which is exactly what the host-carried roster file is
  for.

- **Bots invite players.** `_try_party_seek` extends to solo same-map players
  within level range, using the normal invite RPC + client UI (the player
  consents like any invite). Rare by design: long per-bot cooldown, one
  attempt at a time, and the solo party is abandoned if the player doesn't
  accept within a timeout — a bot never sits leader of a phantom party.

- **Banter is orchestrated, not emergent.** `BotManager` periodically picks
  two near-each-other bots on a map that has a real-player audience and
  scripts one open + one delayed reply (`banter_open` / `banter_reply`
  pools). The delay exceeds the global speech gap so both lines clear the
  budget. No audience → no banter; it exists to be overheard.

- **Offline catch-up.** On spawn of a NON-fresh bot, downtime since the
  roster's `last_seen` converts to levels (`levels_per_hour`, capped by
  `max_catchup`) through `pump_bot_to_level` — the same EXP+mastery path as
  seeding, so the point-reconcile invariant holds. The world keeps living
  between host sessions; matters most for the Steam-lobby topology where
  sessions are days apart.

- **World-map population counts.** The world-map overlay shows an "N online"
  badge per map, fetched on open via a `MapManager` request/receive RPC pair
  (server computes counts from its live map occupancy — bots + players
  indistinguishably, which is the point). No continuous sync; one snapshot
  per open. The minimap already draws bots and needs nothing.

## Consequences

- The roster file is now load-bearing for churn, reputation, and offline
  catch-up — corrupting it degrades to "everyone is a stranger and always
  online," never an error.
- The `_show_emote` RPC signature changes (carries the emote command);
  server and clients ship from the same build in this project, so no
  compatibility shim.
- Churn means a bot a player traded with may be offline next session — that
  is the illusion working, not a bug.
